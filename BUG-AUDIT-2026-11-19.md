## Root causes

1. **Async helpers still write after an `await` without checking who is signed in** (A-8, C-10, D-4, D-9 and half
   of D-5). `cloudSync`/`cloudPush`/`pushOne` got their `gen` checks in the last round; the account-hub loaders
   around them did not. B-7 is the same family with a twist: the pass that starts *during* a sign-out can't be
   caught by a generation check — only the missing `signingOut` guard can.
2. **The three reset paths clear three different sets of fields.** Manual sign-out, session expiry and in-place
   account switch each miss something the others clear (A-7 vs A-9; C-7; D-5). STATE-MACHINES.md step 4 asked for
   one reset used by all paths — still not true.
3. **New features shipped without their guards.** G-2's database exemption (G-4) and ungated button (D-7); the
   E-5 retype fix's interaction with the one-at-a-time flow (E-8) and its baseline lifecycle (E-9); the release
   button next to a checked-in volunteer (D-6).
4. **Fixes whose audience cannot see them** (F-8, F-13): both messages render behind opaque layers that only the
   running app could lift — and in exactly these cases the app never runs.
5. **The release tooling trusts the one machine that has the APK** (H-1): `build` and `release` both succeed
   while silently dropping the Android download from the site.
